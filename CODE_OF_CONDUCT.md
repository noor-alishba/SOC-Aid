# 🤝 SOC-Aid — Code of Conduct

## 🌟 Our Commitment

We are committed to making participation in the SOC-Aid project a respectful, professional, inclusive, and constructive experience for everyone.

Contributors are expected to communicate respectfully, collaborate in good faith, and focus on improving the project.

---

## 🧭 Expected Behavior

Participants are expected to:

- 🤝 Treat others with respect and professionalism.
- 💬 Communicate clearly and constructively.
- 🧠 Consider different technical perspectives.
- 📚 Give and receive constructive feedback.
- 🔎 Focus discussions on the project and its technical goals.
- 🛡️ Take security concerns seriously.
- 👥 Respect the contributions and time of other participants.
- ✅ Accept reasonable corrections and technical disagreements professionally.

---

## 🚫 Unacceptable Behavior

The following behavior is not acceptable:

- Harassment, intimidation, or personal attacks.
- Discriminatory or hateful language.
- Threats or deliberate intimidation.
- Trolling or intentionally disruptive behavior.
- Publishing private or sensitive information without permission.
- Deliberately misleading contributors.
- Unwanted sexual or inappropriate behavior.
- Deliberate attempts to compromise project security.
- Sharing credentials, API keys, or other secrets.
- Any behavior that creates an unsafe or hostile project environment.

---

## 🔐 Security-Related Conduct

SOC-Aid is a cybersecurity project, so contributors have an additional responsibility to handle security information carefully.

Do not intentionally:

- Publish private credentials.
- Commit API keys or access tokens.
- Expose sensitive security data.
- Include real personal information unnecessarily.
- Introduce intentionally malicious code.
- Use project contributions to perform unauthorized security activity.

Security research and testing should be conducted responsibly and only where appropriate authorization exists.

---

## 🧪 Responsible Security Testing

When testing security-related functionality:

1. Use controlled environments.
2. Avoid targeting systems without authorization.
3. Do not expose real credentials or sensitive data.
4. Document security findings responsibly.
5. Follow the project's security-reporting guidance.

For security vulnerabilities, refer to `SECURITY.md`.

---

## 💬 Technical Disagreements

Technical disagreement is a normal part of software development.

When disagreements occur:

- Focus on the technical issue rather than the person.
- Explain the reasoning behind your position.
- Use evidence, tests, and documentation where possible.
- Remain open to alternative approaches.
- Keep discussions constructive.

Different technical opinions should be handled professionally.

---

## 👥 Maintainer Responsibilities

Project maintainers should:

- Encourage respectful collaboration.
- Address inappropriate behavior fairly.
- Keep project discussions focused and constructive.
- Protect contributors from harassment.
- Take security concerns seriously.
- Apply project standards consistently.

---

## 🚨 Reporting Concerns

If you experience or observe behavior that violates this Code of Conduct, report it to the project maintainer through an appropriate private communication channel.

For security vulnerabilities, follow the instructions in:

`SECURITY.md`

Do not publicly disclose sensitive security information before it has been responsibly reviewed.

---

## ⚖️ Enforcement

Violations may result in appropriate actions depending on the severity and circumstances.

Possible actions include:

1. Private warning
2. Request to correct behavior
3. Temporary restriction from project discussions
4. Removal of inappropriate contributions
5. Restriction or removal of participation

The goal of enforcement is to maintain a respectful, productive, and safe project environment.

---

## 🌱 Project Values

SOC-Aid encourages the following values:

### 🛡️ Safety

Security should be treated responsibly.

### 🔎 Evidence

Technical and security claims should be supported by evidence whenever possible.

### 🤝 Collaboration

Good software is built through constructive collaboration.

### 📊 Transparency

Important project decisions should be explainable.

### 👤 Human Responsibility

AI-assisted functionality should not remove appropriate human responsibility.

### 🚀 Continuous Improvement

Feedback, testing, and iteration are essential to improving the project.

---

## 🙌 Final Note

Thank you for helping keep SOC-Aid a respectful, secure, and constructive project.

> **Build responsibly. Communicate respectfully. Keep security and evidence at the center.** 🛡️
